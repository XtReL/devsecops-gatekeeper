## 2. Поправки к обоснованию

### a. Решение по Action и заявления C25-C29

В решении акт пишет, что ядро заявлений подтвердилось «прогонами и положительными контролями (C1, C13-C15, C17-C22, C25-C29)». Это неточно. C27 проверено подсчётом по тексту. C28 и C29 проверены чтением.

Исправленная формулировка: заявления C1, C13-C15, C17-C22, C25 и C26 подтверждены прогонами. C27 подтверждено подсчётом по тексту. C28 и C29 подтверждены чтением. В GitHub Actions они не запускались.

Само решение «принять с условиями» не меняется.

### b. C3, закрепление gitleaks

Подтверждено, что закрепление есть. В режиме Action версия `v8.30.1` закреплена в `go.mod` и `go.sum`. В облачном режиме в `Dockerfile.scanner` есть проверка `sha256sum -c`.

Правильность значения контрольной суммы не сверялась с релизом gitleaks. Акт это говорит в колонке доказательств, но статус П читается шире. Точная формулировка: закрепление присутствует, значение не сверено.

### c. C7, секреты по умолчанию

Вывод относится к дереву коммита `7e2f7b6`. История git не сканировалась. Об этом акт пишет в риске 5. Поэтому слова «реальных секретов не выявлено» нельзя читать как вывод об истории.

Поиск литералов шёл без положительного контроля. Охват поиска в акте не описан. Значит, пропуск литералов в других местах дерева не исключён.

### d. C8, заголовок X-User-Login

Вывод по чтению, не запускался. Он держится на допущении: перед API нет прокси, который сам выставляет заголовок `X-User-Login`.

Сведения об этом допущении получены владельцем ревизии при чтении публичного репозитория. В акте их нет. Здесь они записаны без повторного открытия файлов:

- в репозитории прокси не описан;
- `docker-compose.yml` публикует порт 8080 API напрямую;
- в манифестах k8s нет Ingress;
- пробы liveness и readiness сами подставляют этот заголовок.

Если перед API появится прокси, который задаёт заголовок, вывод нужно пересмотреть.

### e. C16, ключ и шаги composite action

Статус О остаётся, способ: чтение. Для доказательства нужен прогон в GitHub Actions. Например, задать безобидную переменную на шаге `uses:` и проверить, видна ли она во внутреннем шаге.

В акте на ADR 0003 ссылка стоит как довод. ADR 0003 доказательством служить не может. Он описывает решение, а не результат запуска.

### f. Класс «ошибка в тесте похожа на ошибку кода»

В акте записано «не выявлено». У акта нет метода, по которому такие случаи ищутся. Поэтому правильная запись: не искался. Слово «не выявлено» создаёт ложное впечатление, что поиск был.

### g. C4, облачный режим

Статус C4 меняется с Н на О на дату 2026-10-10.

Основание: по данным владельца, развёрнутой облачной системы на эту дату нет. Способ: наблюдение по скриншотам владельца. Облако не запускалось. Скриншоты в репозиторий не добавлены и в этой работе не рассматривались.

Чтение кода в акте этому не противоречит. В коде нет пути, по которому настоящий вебхук получает права на настоящий репозиторий (см. строку C4 акта).

Статус относится к одной дате. Если систему развернут, заявление нужно проверять заново.

Решения акта по облачному режиму не меняются. Условие акта убрать из `README.md` слова «сейчас работает облачный режим» теперь подкреплено наблюдением.

## 4. Находки ревизии вне заявлений

В счёт заявлений они не входят. Обе найдены чтением, без запуска.

**Р1. Порты compose не привязаны к 127.0.0.1.** `docker-compose.yml` публикует порты: Postgres 5433, SpiceDB 50051, Redis 6379, NATS 4222, API 8080. Привязки к `127.0.0.1` нет. Если стек запущен на машине с внешним адресом, эти порты могут быть доступны по сети. Защищённость самих сервисов не проверялась. Способ: чтение.

**Р2. Старые образы в ghcr.** Образы `devsecops-gatekeeper-api` и `devsecops-gatekeeper-scanner` публично лежат в ghcr. Они опубликованы около 4 месяцев назад. Текущий CI их не публикует. Содержимое образов не сверялось с кодом на HEAD. Поэтому образы могут отличаться от текущего кода. Способ: данные владельца ревизии, в этой работе не перепроверялось.
