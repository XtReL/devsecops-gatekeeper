# Правила для агента

- **Перед началом работы** прочитай `docs/adr/` и `docs/tasks/`: архитектурные решения и текущее задание зафиксированы там, а не в чате.
- **Перед каждым push** запусти `scripts/check.sh` и покажи его полный вывод. Скрипт запускает то же, что CI, и падает на первой ошибке; коммит без зелёного `check.sh` не отправляется.
- **PR не сливать.** Слияние в `main` делает человек после зелёного CI.
- **В коде и тестах нет строк, похожих на секреты.** Тестовые «секреты» собираются в рантайме из частей, а не пишутся литералом — иначе сработают gitleaks и GitGuardian на самом репозитории. **Тело — не ниже энтропии, которую требует правило gitleaks (обычно entropy >= 3), повторяющийся паттерн вроде `"a1"×18` (entropy 1.0) её не даёт и попросту не находится сканером.** Годится тело из SHA-256 фиксированной строки (например `printf 'label' | sha256sum | cut -c1-36`, entropy ~3.6) или детерминированный PRNG с алфавитом из разных символов (`internal/engine/testtoken_test.go`, `fakeToken`) — там, где тест должен именно найти находку, проверяйте это фактическим прогоном сканера, а не только видом строки.
- **`cmd/api`, `cmd/scanner` и облачную часть не трогать** без явного задания на это.
- **GitHub Actions — только по полным SHA** коммитов (тег указывается в комментарии рядом).
- **Входы action и контекст GitHub — только через `env`, никогда `${{ }}` внутри `run:`.** Каждый вход (`${{ inputs.… }}`) и каждое значение контекста (`${{ github.… }}`) передаётся в шаг через `env:` и читается в скрипте как `"$VAR"`. Прямая подстановка `${{ }}` в тело `run:` — путь к инъекции в shell (`docs/adr/0003-distribution.md`).
- **При расхождении с ADR — остановиться и спросить**, не менять архитектурное решение самостоятельно.
